# 开发工作流

遵循项目 AGENTS.md、用户当前授权和 CoTree 的权限 / 取消 / 会话恢复规则。先用 ToolSearch 读取实际工具 schema，再调用所需工具。主模型判断任务完成；测试输出和外部结果是证据，不能用自评分或固定审查轮数替代。只在任务需要且当前策略允许时使用 AgentDefinitions / AgentDelegate；模型继承宿主选择，不要求特定供应商。资源相对 Skill 返回的 skillDir 解析，插件根由 pluginRootDir 给出。

读取设计文档、当前工作区变化、入口、调用方和相关测试。把用户目标、已有事实和待验证假设分开。小改动直接完成；较大任务维护项目惯用的执行计划，阶段内记录决策、证据和剩余事项。

缺失信息会实质改变行为或代价时提问，同时推进不依赖答案的工作。已有授权持续有效；不要每一步重复请求开始、设计或提交批准。对复杂方案比较必要的取舍，选择符合当前架构的最小方案。

按独立、可验证的小任务推进。行为变化添加合适测试；调试先复现和定位，随后做最小修改。已有测试或实际失败路径比自述清单更可靠。测试不足以说明外部业务成功时明确分开记录。

只有任务值得拆分且当前权限允许时委派；先读取 AgentDefinitions / AgentDelegate 的 schema，给定范围、资源和交付证据。持久 Group 协作用 SessionDelegate / SessionQuery / SessionMessage；保留取消、预算、回执和子权限边界。单人顺序完成同样有效，不强制并行。

使用独立分支 / worktree 时检查当前改动并遵循仓库惯例；不能把 worktree 当 OS 沙箱。不把其他人的修改暂存或清除。每完成几个可用单元报告实际变化与验证，再继续用户已授权的任务。

交付前检查差异、相关测试和接口文档。主模型结合用户目标判断是否完成，明确剩余限制。不要创建额外循环、完成判定服务或强制评分器。方法细节见 references/methods.md。
