# 工程方法

## 设计

明确输入、输出、边界和既有约束；只讨论影响实现的取舍。

## 测试驱动

新增行为先写有意义的失败用例，确认失败原因，再实现并重构；纯文案或机械变化不强制构造无意义测试。

## 调试

复现 → 收集证据 → 缩小范围 → 验证假设 → 修复 → 回归。

## 协作

独立任务可并行，依赖任务按结果推进；避免多人写同一文件，合并时核对真实差异。

## 审查与反馈

检查风险较高的变化；纠正有证据的问题，不为完成固定审查轮数重复执行。接受外部反馈前先核对代码与目标。

## 计划执行与交付

按可用单元汇报，保留执行证据、剩余事项和可接手的位置；用户明确要求提交或 PR 时再走 Git 工作流。
