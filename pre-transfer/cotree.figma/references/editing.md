# 编辑工作流参考

先读取 tools/list 与所选工具提供的当前 API 文档 / 资源。远程编辑器支持什么以返回的接口为准，不把来源插件专属调用直接复制进 CoTree。

## 目标与恢复

每次操作确认 fileKey、编辑器和页面 / 节点，保存创建结果 ID。需要切页时使用已记录的页面及实际异步 API；不要依赖上一次脚本的内存或全局变量。先只读检查，按用户意图在指定区域做小批更改。新文件只创建一次；不因响应超时创建多个同名文件。

## 脚本与资源

工具的沙箱不等于 Node。不要假设 import、文件系统、网络、console 或 npm 可用；用文档支持的 API，明确 return 所需结果，await 所有异步工作。编辑文本前按 API 加载字体；图片使用真实资产数据或受支持上传结果，不能把下载 URL 当 image hash。颜色、单位、约束和布局根据实际 schema 处理。

## 设计系统

先复用变量集合、语义别名与模式，再建立样式和组件。检查变体集合与组件父子关系，布局优先可响应约束 / 自动布局。实例保留组件来源并绑定变量，避免到处复制分离图形；用户要求局部独立编辑时另行判断。

## 编辑器边界

Design、FigJam、Slides 的节点类型和页面管理不同。FigJam 使用其节点与连接器端点，Slides 使用原生幻灯片接口；不假定它们支持 Design 的 createPage 或 metadata。图表只选当前服务支持的类型。动效需要当前 motion 能力和时间线 API，缺失即记录限制。

## 验证

读取结构 / 属性 / 绑定和实际截图；文字溢出、字体回退、资源缺失及错误约束需要修正。动画另需时间线 / 播放证据。返回真实文件链接与已完成范围；图片预览、本地代码和远端编辑分别报告。
