# Git 工作流

遵循项目 AGENTS.md、用户当前授权和 CoTree 的权限 / 取消 / 会话恢复规则。已提供契约的工具直接使用，缺少契约时再用 ToolSearch；不猜测工具名或参数。需要且策略允许时使用 AgentDefinitions / Agent，当前任务不要求委派。资源相对 Skill 返回的 skillDir 解析，插件根由 pluginRootDir 给出。加载本 Skill 不授予提交或推送权限；已有相应授权时直接推进，无需重复询问。

先通过 Bash 或 PowerShell 执行 node <pluginRootDir>/scripts/inspect.mjs --workspace <实际项目路径>（按当前 Shell 语法引用路径），也可读取 GitStatus / GitDiff 和近期提交。检查当前分支、HEAD、未跟踪文件、暂存与未暂存差异，参考项目提交格式。独立只读检查可以并行；脚本输出不自动 stage 或 commit。

确认本次提交范围，只暂存本任务文件或补丁，保留其他修改和原有暂存状态。已有暂存内容也可能属于其他任务，不能默认全部提交；共享文件中无法确定归属的部分需要先厘清。检查新文件是否含凭据和生成物，不用 git add . 混入无关内容。按项目要求运行相关检查，并区分通过、失败和未运行。

暂存、核对暂存差异、提交、读取结果有前后依赖，必须依次执行。依据实际改动编写简洁消息，解释问题和变化原因；用参数或 UTF-8 消息文件传给 git commit，避免 Shell 插值和引号问题。没有待提交的授权变更时说明现状，不创建空提交。

失败或中断后先读取 HEAD、状态和诊断，确认是否已创建提交或修改文件，再恢复未完成步骤。hook 失败通常没有创建本次提交；修复后重新检查差异并暂存，不用 amend 意外改写前一个提交，也不绕过 hook 或签名。只有用户明确要求 amend 时才按相应范围处理。不要盲目重跑整段命令。

交付真实提交 SHA、分支、改动摘要、实际检查及剩余工作区修改。成功提交不等于推送；没有推送授权就停在本地提交。主模型根据实际证据判断任务结果。
