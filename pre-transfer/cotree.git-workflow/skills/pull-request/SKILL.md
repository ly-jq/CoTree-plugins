# Git 工作流

遵循项目 AGENTS.md、用户当前授权和 CoTree 的权限 / 取消 / 会话恢复规则。已提供契约的工具直接使用，缺少契约时再用 ToolSearch；不猜测工具名或参数。需要且策略允许时使用 AgentDefinitions / Agent，当前任务不要求委派。资源相对 Skill 返回的 skillDir 解析，插件根由 pluginRootDir 给出。已有相应授权时直接推进；加载本 Skill 不扩大授权范围。

确认目标仓库、远程、base/head、当前分支、跟踪关系和未提交改动，不假设基线总是 main。读取与实际基线比较的全部相关提交及差异，不能只看最后一个 commit；远程状态陈旧时先刷新所需引用。需要提交时按本插件 commit Skill 处理，保留无关修改。只在用户要求推送 / 创建 PR 的范围内进行远程操作。

先查同一仓库与 head/base 是否已有 PR；已有目标 PR 时按请求更新，避免重复创建。独立只读检查可以并行；创建分支、提交、推送、创建 PR 必须按实际依赖顺序执行。正常推送功能分支；推送被拒绝时检查远程变化，不用强推绕过。使用已授权的 GitHub 工具或 gh。

遵循仓库 PR 模板。标题说明最终变化，正文描述具体问题、改变后的行为、必要实现信息、实际验证和限制；范围改变后同步修订，省略聊天过程。使用结构化工具参数，或把正文写入 UTF-8 文件后用 gh pr create/edit --body-file 提交，保留换行且不插值执行代码。没有验证的内容标明未验证，不把进程退出或子 Agent 报告当作业务结果证明。

推送或创建请求超时、取消或结果不明时，先查询远程分支 SHA 和匹配的 PR，核对已经产生的效果，再恢复剩余步骤。不要盲目重试创建。认证或网络失败时保留本地提交，说明失败位置和下一步。

交付实际 PR URL、head/base、当前状态、关键改动、实际验证和剩余问题。PR 创建成功不代表 CI 已通过或可以合并；合并和删除分支按用户授权及仓库规则另行处理。
